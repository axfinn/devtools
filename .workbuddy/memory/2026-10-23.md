## Debug: 部署站点 t.jaxiu.cn 聊天室 WS 异常 (根因定位)
- 实测: / 、/chat、/pet、/dev/avatar 均 HTTP 200; 前端 /assets/*.js 与 /widgets/{pet-widget.js,yunfan.glb,vendor/three.module.js} 均 200 -> 页面与静态资源正常。
- 后端 API /api/chat/rooms 返回真实数据(200); 反代为 腾讯云 EdgeOne(eo-* 头) + 源站 nginx/1.29.3 -> Docker Go(8082)。
- WS 端点: wss://t.jaxiu.cn/api/chat/room/<id>/ws。
- 根因: 浏览器默认 HTTP/2 连 EdgeOne, EdgeOne 回源协议\"跟随\"=HTTP/2, 导致 nginx 收到 h2 连接上的 upgrade 请求, Go gorilla/websocket 在 h2 上无法升级 -> 400 Bad Request。
- 验证: curl --http1.1 强制 h1.1 实测 -> 101 Switching Protocols 成功(收到 system 加入消息); 默认 h2 -> 400。
- 修复: (1) EdgeOne 控制台该站点\"回源协议\"改为 HTTP/1.1(或开启 WebSocket 加速, 自动 h1.1 回源); (2) 源站 nginx 确认 chat WS location 配 proxy_http_version 1.1 + Upgrade/Connection 转发 + 长超时。
- 注: ws_monitor.go 幂等关闭改动(上一轮)与本次 400 无关, 但保留(编译通过)。

## 修正: WS 400 根因精准定位 (对照实验)
- 用户确认 nginx 配置无误。对照实验坐实根因:
  A) h1.1 故意缺 Upgrade 头 -> 400 + Sec-Websocket-Version:13 (与浏览器现状同症状)
  B) h1.1 完整头 -> 101 成功 (证明 nginx 正确透传 Upgrade 头)
  C) h2 完整头(浏览器实际) -> 400
- 结论: nginx 与 gorilla 均无问题。根因=EdgeOne 回源协议跟随为 HTTP/2; h2 协议无 Upgrade 头机制, nginx 收不到 WS 升级信息, 回源到 Go 时 Upgrade:websocket 头丢失 -> Go 拒绝 400。
- 修复落点: EdgeOne 控制台该站点\"回源协议\"改为 HTTP/1.1 (或开启 WebSocket 加速, 自动 h1.1 回源)。nginx 无需改动。

## 最终根因确认: wss 连接 failed (t.jaxiu.cn 聊天室)
- 用户明确报错="wss 连接 failed"，浏览器侧。
- 决定性对照(同端点同TLS, 唯一变量 h1.1 vs h2):
  * EdgeOne 已开 h2 接入: http1.1 GET 与 http2 GET /api/chat/rooms 均 200。
  * Node ws (纯 h1.1 客户端) 连 wss://t.jaxiu.cn -> OPEN ok。
  * 浏览器 (ALPN 协商 h2) -> wss 连接 failed。
- 根因: EdgeOne 回源协议=跟随; 浏览器走 h2 连 EdgeOne -> 回源 h2 -> h2 无 Upgrade 头机制 -> 到达 Go 时 Upgrade:websocket 头丢失 -> gorilla 拒绝 -> 浏览器 failed。
- nginx 无罪(已确认, Node h1.1 测试证明 nginx 在 h1.1 下完美)。本地 docker 纯 h1.1 故正常。
- 修复落点: EdgeOne 控制台 站点 t.jaxiu.cn -> 回源协议改 HTTP/1.1 (或规则引擎按 /api/chat/ 路径设 h1.1 回源)。nginx 不动。
- 注: 之前 curl 本地/远程 400 多是被 curL 头问题干扰(本地 curl h1.1 也400但 Node h1.1 成功), Node ws 因只走 h1.1 掩盖了 h2 陷阱。本次用 h1.1客户端成功 vs h2客户端(浏览器)失败 对照坐实。

## 修复: 移动端"看不全页面"(根因=聊天室全局锁滚动 + 高度溢出)
- 现象: 手机端经常看不全页面。全局排查定位两个根因:
  1. ChatRoom.vue 原在 onMounted 里 `document.querySelector('.main-content').style.overflow='hidden'` 锁死主内容区滚动, 但 App.vue 用 `<keep-alive :exclude="[]">` 缓存所有页面, 离开聊天室只触发 onDeactivated 不触发 onUnmounted, 还原代码永不执行 -> 进过一次聊天室后, 后续任意页面(含移动端)主内容区无法滚动 = "看不全"。这是偶发/全局元凶。
  2. .wx-app 写死 `height: calc(100dvh - 40px)`, 但移动端 .mobile-main 顶部已有 padding-top:71px(固定头56+15), 整体比可视区高 30px+, 输入栏/底部被推到屏幕外。
- 修复:
  - 改用 body class `chat-room-active` 控制外层滚动(App.vue 全局 style 加 `body.chat-room-active .main-content{overflow:hidden}` + 移动端 `margin-top:56px; height:calc(100svh-56px); padding:0; overflow:hidden` 让 .wx-app 精确填满头部之下区域, .wx-app 改 height:100%)。在 onMounted/onActivated 加 class, onDeactivated/onUnmounted 移除, 彻底消除 keep-alive 残留。
  - ChatRoom scoped 加 `@media(max-width:860px)` 单栏布局(可见面板 flex:1 撑满, 去掉固定 300px 溢出), 输入栏加 `env(safe-area-inset-bottom)` 安全区。
  - index.css 的 body/#app min-height 由 100vh 改 100dvh(回退 100vh)。
- 注: 本沙箱 pnpm 因 broker 拦截 symlink 无法 install, 无法在此 build 出新 dist; 需用户在真机 `./deploy.sh docker`(或 pnpm build + docker cp) 部署生效。
