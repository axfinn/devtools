## 用发布脚本部署（含移动端修复）

- 用户要求"用发布脚本部署"。目标：把上一轮的移动端修复（ChatRoom.vue / App.vue / index.css）真正编译进 dist 并发布。
- 沙箱里 pnpm 构建一直失败的根因已彻底查清：WorkBuddy 通过 `NODE_OPTIONS=--require=.../node-language-shim.cjs` 把 brokered-fs 垫片注入**每一个** Node 进程，垫片会拒绝软链接创建 → pnpm 挂死。
- **解决办法（关键，可复用）**：执行 pnpm 前 `unset NODE_OPTIONS` 并把系统 Node 放 PATH 最前：
  `export PATH=/opt/homebrew/bin:$PATH && unset NODE_OPTIONS && pnpm install --frozen-lockfile --config.store-projects=false --config.node-linker=hoisted`
  之后 `pnpm build` 即正常产出 dist。代理照常从终端 export 的 HTTP(S)_PROXY 走（127.0.0.1:7897）。
- 改了 `deploy.sh` 的 `build_frontend_host`：若 `frontend/dist` 已存在且非空，直接复用、不再回退去运行容器提取旧 dist（否则会把新改动覆盖掉）。
- 用 `HOT_DEPLOY=1 ./deploy.sh docker` 完成发布：基于本地缓存 `devtools-devtools:latest` 叠加新 dist（零拉取、不动 daemon、不影响其他容器）。新容器健康 200，dist 含 `safe-area-inset-bottom` / `chat-room-active` / `wx-sidebar`。
- 其他容器（ocr-service / asr-service / devtools-redis）全程未受影响。
